# 慢慢点 · 运行 Skill（顾客点餐）

## 触发条件

用户希望在麦当劳选餐、理解套餐与总价、控制预算、修改选择、用文字沟通，或使用可访问方式操作。

## 处理步骤

1. **读取当前草稿**：若存在未完成草稿，先告知「已经保留你之前的选择」，不重置
2. **补齐最小必要信息**（一轮只问一个主要问题）：门店/取餐方式 → 人数与数量 → 预算 → 明确限制。已给过的信息不重复问；不问年龄、职业、残疾类别
3. **查真实门店**：query-nearby-stores（用户给城市/地点；到店自取 beType=1，得来速 beType=5）
4. **查当前菜单**：query-meals（仅匹配该门店在售商品）
5. **查详情**：query-meal-detail（套餐组成、可替换项、差价；supportModify 标注【可特调】，用户问「查看特调」才展开）
6. **给出候选**：最多 3 个，每个说明「包含什么、满足哪些已确认需求、哪些仍未知」；保留「看看其他选择」「不选了」「修改需求」
7. **用户选择/修改**：改一项只改一项；改后旧报价与旧确认失效
8. **真实核价**：calculate-price（金额单位为分，展示除以 100）；绑定门店/方式/商品/数量/选项/优惠/总额展示摘要
9. **收尾三选一**：
   - 继续修改 → 回到草稿
   - 只需沟通 → 生成标注「未下单」的沟通卡（含用户选择与待核实事项；不出现「已发送给店员」）
   - 明确确认且授权创建 → 走独立确认流程（当前版本写操作关闭，如实告知）

## 禁止

- 把模糊肯定当交易确认；「随便」「你看着办」不自动授权超预算或下单
- 根据模型常识补商品属性（辣度/配料/过敏）——未知就标注「我还不能确定这一点」
- 自动领取优惠券、默认加购、消耗积分
- 为使用券添加用户不需要的商品
- 制造取餐码；创建结果不明时重试
- 将「不要」吞成「要」、将一份默默变两份——数量与否定须复核

## 可访问输出要求

- 语义化短句 + 结构化列表；商品名、组成、数量、价格、状态全部有文字
- 金额、否定、数量变化时主动复述确认
- 用户提供大字/读屏偏好时保持并沿用；切换方式不丢草稿

## 失败恢复

- 401/连接失败 → 提示核验 MCP 连接，不泄露 Token，不无限重试
- 网络断开 → 明示离线状态与上次查询时间，禁止未核价的下一步
- 报价过期 → 「报价可能有变化，我们重新查一下，你的选择都还在」
- 创建未知（未来开放写入后）→ 「正在核实是否已创建，请先不要重复下单」

## 依赖与已知限制

- 依赖：麦当劳真实 MCP（mcd.cn，35 工具，凭证由维护者配置）
- 当前版本：只读到核价为止；下单/付款走官方渠道由用户自行完成
- 手语输入：实验能力，未开放（条件不满足时明确告知并回退文字）
- 商品信息、价格及供应状态以麦当劳官方渠道实时结果为准
