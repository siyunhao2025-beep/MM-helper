# 无障碍回应模式

用户提到读屏、大字、文字沟通、手部操作、节奏、商品名难记，或直接说“慢一点”时读取本文件。先询问操作偏好，省略身份判断。

## 目录

1. 共同入口
2. 安心慢选
3. 极简朗读
4. 文字沟通
5. 直接比较
6. 中断与恢复

## 1. 共同入口

统一问法：

> 怎样操作对你最方便？可以选：一步一问 / 朗读式短句 / 全程文字 / 直接比较，也可以用自己的话说。

用户已经表达偏好时直接采用，无需重复询问。所有模式共享同一份当前会话草稿，切换模式只改变表达方式。

共同规则：

- 一轮推进一个主要动作。
- 价格、数量、状态与排除项都写成文字。
- 首屏最多三个候选。
- 每一步都提供继续、修改和暂时结束。
- 当前状态始终写明 `DRAFT`、`QUOTED`、`HANDOFF_READY` 或 `STOPPED`。

## 2. 安心慢选

适合希望节奏从容、商品名仍在熟悉或希望逐步确认的用户。

输出顺序：

1. 复述已经知道的一件事。
2. 只问当前最关键的问题。
3. 给 2～4 个短选项与“我再说说”。
4. 等待用户回答后再进入下一步。

示例：

```text
我记住了：两个人，预算三十元，希望避开辣味。
先选门店。你想用商圈、地标，还是直接说门店名？
```

## 3. 极简朗读

适合读屏或希望听清每个字段的用户。使用编号列表，精简装饰符号、表格与重复链接。

每个候选依次朗读：

```text
候选一。
名称：……
数量：……
核价：……
已确认：……
待确认：……
你可以说：选一、听详情、换一批、暂时结束。
```

金额同时读出元和角分含义；零份、总份数、排除项和“尚未下单”放在靠前位置。

## 4. 文字沟通

适合偏好打字、希望店员在同一设备回复或当前环境较嘈杂的用户。

沟通卡格式：

```text
【沟通卡｜请协助核对｜尚未下单】
门店：{本轮回执门店名}（编码：{storeCode}）
取餐方式：{本轮回执方式}
我想要：
1. {商品展示名} × {数量}（选项：{选项展示名}）
已确认避开：{本轮证据已确认的排除项}
请协助确认并避开：{仍待核实的排除项}
优惠：保持原样（当前未选择优惠） / 已按本轮报价绑定 {数量} 项
请协助确认：{其他待核实事项}
当前核价：¥……
核价时间：{带时区时间}
核对完成后，请把选择交给食客本人。
```

空状态行按本轮证据省略。卡片由用户自己出示，门店接收状态只依据现场或官方回执呈现。

## 5. 直接比较

适合已经清楚需求、只想比较少量方案的用户。

使用一致字段展示最多三个候选：

```text
候选 A：总额 / 已确认 / 待确认 / 与原清单差异
候选 B：总额 / 已确认 / 待确认 / 与原清单差异
候选 C：总额 / 已确认 / 待确认 / 与原清单差异
```

优惠方案先标 `EQUIVALENT_BASKET` 或 `CHANGED_BASKET`。清单变化时逐项写出增加与减少内容。

## 6. 中断与恢复

用户暂停时输出：

```text
当前状态：STOPPED｜尚未下单
已经选好：……
仍待确认：……
下次可以从“继续刚才的草稿”开始。
```

恢复时先说：

> 你之前的选择还在，我们从这里继续。

然后复述门店、人数、预算、排除项、已选商品和报价状态。报价时间较早或绑定字段已变化时，先重新核价。
